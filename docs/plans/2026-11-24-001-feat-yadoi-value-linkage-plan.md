# feat: 芽豆有物物品估值联动到芽豆资产

## Summary

用户在芽豆资产（yadoA）和芽豆有物（yadoI）登录同一个芽豆账号，并在芽豆资产里授权以后，账户页多一行只读的「芽豆有物 · 物品估值」= 持有物品的购入价合计 × 折扣（默认 7 折，可调）。用户可以选这个数要不要计入净资产。

- **要授权**：苹果审核规则 5.1.2(ii)（全球适用）写明「为一个用途收集的数据，换用途要再取得同意」。物品价格是为芽豆有物记录的，拿到芽豆资产算净资产属于换用途。所以不管上架哪些地区都要授权，并且能随时取消。
- **数据走服务器，由 yado_hub 中转**：芽豆资产 → yado_hub（查授权）→ yadoI_be（只回一个汇总数）。芽豆资产不直接调 yadoI_be，也不需要用户重新登录。
- **芽豆资产本机不存成真账户**：不改 SwiftData 模型，不进同步、导出和 AI。
- **上线时机**：芽豆有物还没上架，芽豆资产 1.0 可以带上代码，但入口要由服务端开关控制，芽豆有物上架后再打开。

## 一、需求

### 1.1 用户看到什么

**账户页**（已授权，且「显示在账户页」打开）

- 账户分组列表最下面单独一组「芽豆有物」，只有一行：
  - 标题：物品估值
  - 金额：¥ 估值
  - 副标题：购入价 ¥X × 7 折 · N 件；有没填价格的物品时加一句「另有 M 件没填价格」
  - 不计入净资产时，金额旁标「不计入净资产」
- 顶部汇总卡片的总资产、净资产按「计入净资产」开关决定是否加上这个数。
- 点这一行进入详情：在用、退役各多少，没填价格的件数，更新时间，折扣和开关的快捷入口。
- 只读：不能记账、转账、调余额，不出现在任何选账户的地方。

**我的 → 数据联动**（新页面，放在「数据」分组，紧挨「云端同步」）

- 列出可联动的芽豆 App，现在只有芽豆有物一项。
- 状态：
  - 未授权：说明会读什么、不会读什么，然后点「授权」。
  - 已授权、有数据：显示估值和更新时间。
  - 已授权、没数据：「芽豆有物里还没有同步到这个账号的物品」，并附上获取芽豆有物的入口。
- 已授权时的设置：显示在账户页（开关）、计入净资产（开关，默认开）、折扣（10%～100%，步长 5%，默认 70%）、取消授权。
- 取消授权后账户页那一行立刻消失，本机缓存的数也一起清掉。

**更多芽豆产品**

- 芽豆有物那张卡片多一句「可联动：把物品估值算进净资产」；已联动的话改成「已联动」，点了进数据联动页。
- 前提：yado_run 里给 yadoi 打上 `series`，而且状态对外（见「五、上线时机」）。

**芽豆有物这边**（第二期，可以不跟第一期一起做）

- 设置里也加「数据联动」：看到「芽豆资产正在读取你的物品估值」，可以在这里取消。
- 把引导页写死的产品列表换成和芽豆资产一样的「更多芽豆产品」页（`/api/series.json`）。

### 1.2 计算口径

- **算哪些物品**：在用（`in_service`）和退役（`retired`），不算已卖出（`sold`）和已删除的物品，和芽豆有物统计页「持有购入总值」用同一套口径。没填购入价的物品跳过，单独记件数。
- **估值** = 购入价合计 × 折扣。折扣只是一个全局比例，以后可以按分类、按购买年限，或接入市场价。
- **币种**：芽豆有物不记币种，界面上也写死了 ¥；芽豆资产只支持人民币。所以直接按人民币算。
- **名称**：芽豆有物自己的规定是，购入价合计不能叫「总资产」，也不能暗示是实时估值。芽豆资产这里因为乘了折扣，叫「物品估值」，副标题写明是怎么算出来的。

### 1.3 不做（第一期）

- **净资产趋势图不含这个数**：没有历史数据，硬加进去会让最后一天突然跳一下。图下面加一句说明。以后如果要做，从授权那天开始每天在本机记一个快照。
- **不发给 AI**：不进 AI 对话和语音记账的上下文。发给 AI 又是一个新用途，要另外说明。
- **不进导出和备份。**
- **不显示单件物品明细**：只读汇总数，这也是授权时写给用户的承诺。

## 二、合规

| 依据 | 要求 | 对这个功能的意思 |
| --- | --- | --- |
| 苹果审核规则 5.1.2(ii)（全球适用） | 为一个用途收集的数据，换用途要再取得同意 | 要单独授权，不能默认打开 |
| 苹果审核规则 5.1.1(ii) | 要给用户方便的方式撤回同意 | 数据联动页可以随时取消授权 |
| 苹果审核规则 5.1.1(i) | 隐私政策要写清所有用途 | 两个 App 的隐私政策都要写 |
| 中国大陆《个人信息保护法》第 14 条（如果上架中国大陆） | 处理目的变了要重新取得同意 | 同上，已被苹果的要求覆盖 |
| 欧盟 GDPR 目的限制（如果上架欧盟） | 新用途要和原用途相容，或者另外取得同意 | 同上 |

结论：**要授权**，而且和上架哪些地区无关。

授权的做法：

- 照芽豆资产现有的 AI 处理同意（`AIProcessingConsentSheet` / `AIProcessingConsentView`）做一个「数据联动授权」弹层和页面。
- 授权文案写清楚三点：
  - 读什么：芽豆有物里在用和退役物品的购入价合计、件数；
  - 不读什么：物品名称、照片、分类和其他明细；
  - 怎么取消：我的 → 数据联动。
- 授权记录存在服务端（yado_hub），按账号走，不按设备。
- 只读汇总数是「最少必要」：服务器之间只传几个数字，不传明细。

要同步改的法律文档（yado_run）：

- `legal/yadoa/{zh,en}/privacy.md`：加「经你授权，从芽豆有物读取物品购入价合计」，第 160 行「每个服务只能访问自己需要的数据」那段补一句联动。
- `legal/yadoi/{zh,en}/privacy.md`：**芽豆有物现在还没有隐私政策**，上架前本来就要写，写的时候带上「经你授权，把物品购入价合计提供给芽豆资产」。
- `sharing.md` 是第三方清单，同一开发者的两个 App 之间不算第三方。但为了透明，可以在 yadoa 的 sharing.md 末尾加一节「芽豆系列 App 之间」。

## 三、技术方案

### 3.1 数据从哪来：三种方式对比

| 方式 | 做法 | 问题 |
| --- | --- | --- |
| **A. 经 yado_hub 中转（推荐）** | 芽豆资产用已有的 hub 令牌调 hub；hub 查授权后，用已有的机器凭证调 yadoI_be 的内部接口，拿汇总数 | 芽豆有物得登录同一账号、数据同步到了服务器（本来就是需求的前提） |
| B. 芽豆资产直接调 yadoI_be | 芽豆资产登录时多申请一个 yadoi 资源 | 已登录的用户都要重新登录；资源配错会让所有人被踢下线（`invalid_target` 会被当成凭证吊销）；拿到的令牌能读写全部物品，权限太大 |
| C. 本机 App Group 共享 | 两个 App 加同一个 App Group，芽豆有物把汇总数写进共享目录 | 只有两个 App 装在同一台手机上才有用；对不上是不是同一账号；芽豆有物没打开过就不会更新 |

选 A 的理由：

- **不用重新登录**：芽豆资产已经能拿到 hub 的令牌。
- **不新增服务之间的连接**：hub 已经有 yadoI_be 的地址和机器凭证，注销账号时就是这样调用的（`ACCOUNT_DELETION_SERVICES`）。
- **授权放在中立的地方**：以后芽豆有物也能看到并取消授权。再加别的联动（比如芽豆有物显示芽豆资产里买东西花的钱），只要多一条授权记录。
- **符合已经定下的方向**：公共能力放后端服务。

### 3.2 各仓库改动

**yadoI_be**

- 新增内部接口 `GET /internal/v1/users/{userId}/item-value-summary`：
  - 机器凭证鉴权，沿用 `requireMachine`；
  - `hide: true`，不进 openapi.json；nginx 本来就拒绝 `/internal/`。
- 返回：
  - `inServicePurchaseTotal`、`retiredPurchaseTotal`
  - `pricedItemCount`、`unpricedItemCount`
  - `lastItemUpdatedAt`
- 口径和 iOS 端的 `HeldPurchaseTotalSummary` 一致：排除 `sold` 和 `deletedAt` 不为空的物品，购入价为空的只计件数。
- 金额用字符串，保留两位小数，避免浮点误差。

**yado_hub**

- 新模块 `links`，新表 `data_links`：
  - 字段：`user_id`、`source`（yadoi）、`target`（yadoa）、`scope`（item_value_summary）、`granted_at`、`revoked_at`；
  - 主键是 (user_id, source, target, scope)，重复授权可以反复调。
- 接口：
  - `GET /v1/links`：当前用户的联动状态列表。
  - `PUT /v1/links/{source}/{target}`：授权。
  - `DELETE /v1/links/{source}/{target}`：取消。
  - `GET /v1/links/yadoi/yadoa/item-value-summary`：查授权；没授权返回 403；授权了就调 yadoI_be，原样转出汇总数。
    - 单次超时 5 秒。
    - 超时、失败返回 502，App 显示上次缓存的数。
- 可联动的来源由环境变量控制（例如 `DATA_LINK_SOURCES=yadoi`）。没配的时候 `GET /v1/links` 返回空列表，App 就不显示入口（见「五」）。
- 注销账号：hub 在编排注销时顺带删掉这个用户的 `data_links`。
- `PRODUCT_CODES` 已经有 yadoa、yadoi，不用改。

**yadoA**

- **新的 `LinkedAssetsStore`**：
  - 读联动状态和汇总数，在账户页出现、下拉刷新时请求，最多 5 分钟一次；
  - 上一次的结果按用户 ID 缓存在本机，没网时显示缓存的数和更新时间；
  - 退出登录、取消授权时清掉。
- **设置存本机**，按用户 ID 分开存，不改 SwiftData 模型，所以不用做数据迁移。存这三样：显示在账户页、计入净资产、折扣。以后要多设备一致，再搬到服务端。
- **账户页**：
  - `AccountListView` 在类型分组后面加「芽豆有物」组；
  - 行的外观复用 `AccountRowPresentation`，这个结构可以不依赖存储的 `Account`；
  - `AccountSummaryPresentation.summary` 多传一个「联动资产」参数。
- **资产分析页**：「计入净资产」打开时，构成和排行里加上这一项，样式和普通账户分开。
- **新路由**：`AccountsRoute` 加 `.linkedItemValue`，用来打开详情；`ProfileRoute` 加 `.dataLinks`，用来打开数据联动页。新路由要实现 `hasOwnBottomBar`。
- **授权**：照 AI 处理同意做弹层和页面，授权记录以 hub 为准。
- **更多芽豆产品**：`SeriesProductsView` 里，yadoi 卡片加联动说明。
- **不碰的地方**：同步、导出、语音和 AI 上下文、余额重建、选账户的列表。
- **中国大陆地区**：拒绝隐私政策后进入的离线模式下，整个联动不显示，因为要联网。

**yado_run**

- 补 yadoa 的隐私政策、新建 yadoi 的隐私政策（见「二」）。
- `products.ts` 里给 yadoi 加 `series`。

**yadoI**（第二期）

- 加 hub 资源，因为还没上架，加资源要求重新登录也没关系。
- 加「数据联动」设置页和「更多芽豆产品」页。

**PROJECTS.md**

- 在「跨仓库要守的约定」里加一条「数据联动」：授权由 hub 管；来源产品的后端提供只读汇总的内部接口；新联动要先改两边的隐私政策。

## 四、边界情况

| 情况 | 表现 |
| --- | --- |
| 芽豆资产没登录 | 不显示联动入口，也不显示那一行 |
| 已授权，但芽豆有物从没登录过或登录的是别的账号 | 汇总数为 0 件：数据联动页提示「芽豆有物里还没有同步到这个账号的物品」；账户页不显示那一行 |
| 芽豆有物有还没同步上去的改动 | 显示的是服务器上的数，带更新时间 |
| 全部物品都没填价格 | 账户页不显示那一行，联动页提示「物品都还没填购入价」 |
| hub 或 yadoI_be 暂时出问题 | 显示缓存的数，标「更新于 …」；没有缓存就不显示那一行 |
| 用户注销账号 | hub 删掉授权记录，芽豆资产清掉缓存 |
| dev 和线上 | 各走各的 hub 和 yadoI_be，数据不混 |

## 五、上线时机

- 芽豆有物还没上架，芽豆资产马上要上架。
- 建议：代码可以跟芽豆资产一起发，但**线上 hub 先不配 `DATA_LINK_SOURCES`**，芽豆资产就看不到入口。dev 环境配上，可以先测起来。
- 芽豆有物上架那天：
  1. 线上 hub 配上 `DATA_LINK_SOURCES`；
  2. yado_run 发布 yadoi 的隐私政策、打开 series；
  3. 芽豆资产不用发新版本。
- 如果芽豆资产 1.0 赶时间，也可以整个功能放到 1.1，上面的设计不受影响。
